### 15. Threshold min/max logic — CRITICAL BUGS

**PARTIAL (with bugs).** Two separate threshold-checking code paths exist:

**Path 1 — EnvironmentController** (`app/Http/Controllers/EnvironmentController.php:105-117`):

```php
private function tempStatus(float $temp, array $t): string {
    if ($temp > $t['temp_max']) return 'Alert';
    if ($temp > $t['temp_max'] - 1.5) return 'Watch';
    return 'OK';
}
private function humStatus(float $hum, array $t): string {
    if ($hum > $t['hum_max']) return 'Alert';
    if ($hum >= $t['hum_max']) return 'Watch';
    return 'OK';
}
```

- **Bug A — `temp_min` and `hum_min` are completely ignored.** Both methods only check against their `_max` thresholds. A temperature of 5°C (below the default 18°C `temp_min`) returns `OK`. The "below min" condition is **silently never triggered**.
- **Bug B — `humStatus` confusing boundary**: `$hum >= $t['hum_max']` is only reachable when `$hum === $t['hum_max']` (because `$hum > $t['hum_max']` is caught first). Being exactly at max yields 'Watch' instead of 'OK', which is inconsistent with `tempStatus` where exactly at max yields 'Alert' (since `$temp > $t['temp_max']` excludes equality).

**Path 2 — DashboardController** (`app/Http/Controllers/DashboardController.php:122-126`):

```php
if ($env->temperature_c > 30 || $env->humidity_pct > 70) {
    $status = 'Alert';
} elseif ($env->temperature_c > 28.5 || $env->humidity_pct >= 70) {
    $status = 'Watch';
}
```
- Uses **hardcoded thresholds** (30°C/28.5°C/70%) instead of the user-configurable settings from the `settings` table. Ignores `temp_min` and `hum_min` entirely as well.

**Summary**: The `temp_min` and `hum_min` thresholds are stored, editable, and displayed, but **never evaluated** in any code path. Three separate bugs exist.
