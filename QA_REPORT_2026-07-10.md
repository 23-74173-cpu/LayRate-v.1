### Critical issues found at baseline (both fixed)

**1. The suite had never run on this machine — and appeared 86-failed when it did.**
Root cause: `.env` has `APP_URL=http://localhost/LayRate/public` (XAMPP subfolder). In feature tests, `route()` generates URLs whose path includes `/LayRate/public/...`, which matches no route → 44+ tests failed with 404 despite the routes being fine.
**Fix:** added `<env name="APP_URL" value="http://localhost"/>` to `phpunit.xml`. This is safe for both machines (PHPUnit's value takes precedence over `.env` in the testing process only).
Also: the `layrate_testing` database did not exist here (created, empty, isolated), and `DB_SOCKET` in `phpunit.xml` is a Linux path that must be blanked on Windows (`DB_SOCKET= php artisan test`).

**2. The Unit test suite was silently never running.**
`phpunit.xml` only registered `tests/Feature`; `tests/Unit/Services/EnvironmentStatusServiceTest` (13 tests) was skipped by every `php artisan test` run.
**Fix:** registered the `Unit` suite in `phpunit.xml`.

**3. Live database was 6 migrations behind the code** (this machine only).
`/feed/live-data` returned **HTTP 500** — `Unknown column 'feed_batches.unit_cost'` — because the July 4–8 migrations (production-log override columns, `deactivation_cause`, nullable log FKs, `logged_via`, egg-weight settings, feed brand/cost/stock) had never been run here.
**Fix:** ran `php artisan migrate` (all six verified additive-only before running — no drops, no destructive statements). `/feed/live-data` now returns 200. All other pages re-verified clean.

**Safety proof:** a new sentinel test (`tests/Feature/DbSanityCheckTest.php`) asserts the test suite is connected to `layrate_testing` before anything runs, and exact row counts of all 12 live data tables were snapshotted before and after this QA pass — **identical** (hens 180, production_logs 630, etc.). The live DB was never touched by tests.
